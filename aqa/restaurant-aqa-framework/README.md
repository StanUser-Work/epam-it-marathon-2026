# Restaurant E2E & API Test Automation Framework

Цей фреймворк автоматизує наскрізні сценарії для функціоналу **Групового Pre-Order (Напрям 1)** ресторану за рівнями складності 1, 2 та 3.

## Обраний напрям та підхід
- **Напрям:** Напрям 1 — Груповий pre-order (Owner Flow: перегляд учасників, консолідація кошиків, підтвердження та видалення гостя).
- **Стек:** Playwright + TypeScript + Page Object Model (POM).
- **Піраміда тестів:**
  - **UI (E2E):** Покриття основних клієнтських сценаріїв (відображення страв, статусів `Submitted`/`Still choosing`, підтвердження консолідованого замовлення, діалог видалення гостя).
  - **API:** Тестування безпеки та валідації (доступ без авторизації, не-Owner, неіснуючі сесії — коди 400/401/403/404).

## Рівні складності
1. **Рівень 1 (@level1):**
   - Перегляд списку учасників, кількості та сум страв.
   - Відображення незавершених кошиків («Still choosing») та плашки попередження.
   - Опрацювання порожньої групи («Participants haven’t added any dishes yet»).
2. **Рівень 2 (@level2):**
   - Консолідація однакових страв («Caesar Salad × 3») та підсумовування Grand Total.
   - Валідація блокування кнопки Submit при відсутності підтверджених страв.
   - Успішний Submit через модальне вікно та зміна статусу на «Sent to Restaurant».
3. **Рівень 3 (@level3):**
   - Відображення кнопки «Remove Guest» виключно біля звичайних гостей (не для Owner).
   - Діалог підтвердження видалення та автоматичний перерахунок суми.
   - API валідація спроб видалення неіснуючих учасників.
4. **Завдання із зірочкою (⭐️):**
   - Хмарний CI/CD пайплайн у GitHub Actions (`.github/workflows/aqa-pipeline.yml`) з автоматичним збереженням HTML-звітів, скріншотів та трейсів падінь.
